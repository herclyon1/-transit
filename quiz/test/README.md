# 交付前必过的验收（不要跳过）

## 为什么存在这个目录

v18~v27 之间每一版上线后用户不到 10 秒就能发现恶性 bug，而我这边的测试全是绿的。
根因不是数据，是**验收方式测错了东西**：

- 用 `svg.call(zoom.transform, ...)` 程序化设定缩放 —— 它不带 `sourceEvent`，走的是和真实手势
  **不同的代码分支**，手势相关的 bug 一个都测不出来。
- 只做数据审计（面积/重叠/名称）—— 看不见任何视觉与交互问题。
- 只在桌面视口截图 —— 手机视口下的层序、标注位置、性能全都不一样。

用户实际报过的四个恶性 bug——画布盖住标记与小岛层、争议标注被扔到屏幕外几万像素、
捏合抖动、放大不刷新高精度——**全部只能在真人式会话测试下暴露**。

## 怎么跑

```bash
cd <仓库根> && python3 -m http.server 8765 &
node quiz/test/usersession.js http://127.0.0.1:8765/quiz/japan-map-quiz.html s
node quiz/test/pinch.js       http://127.0.0.1:8765/quiz/japan-map-quiz.html
```

- `usersession.js`：手机视口 390x844 + 4x CPU 降速 + 模拟 4G 延迟，用**真实输入事件**
  走完「开页→東亜→滚轮放大→拖动→点单元→回全图→点标记→大日本→浏览→回東亜」，
  每步截图并拼成一张联系表 `s-contact.png`。**必须把联系表逐张看一遍**，不能只看 ✅。
  退出码非 0 即为不合格。
- `pinch.js`：CDP 派发**真实双指捏合**，检查缩放倍率是否单调（回跳=抖动）、
  画布是否残留 CSS 变换、帧时分布。

## 已知的红线（改代码时别踩）

1. 画布必须垫在 SVG 之下：`#eaCv{z-index:0}` + `svg#map{position:relative;z-index:1}`。
   否则绝对定位的画布会盖住标记、名称标签、海域虚线和高精度小岛层。
2. 画布必须与 SVG **同帧同源**：缩放事件里同步调 `eaDrawNow()`，不要改回 rAF 合并，
   否则一帧内两个 zoom 事件会让 SVG 与画布差一帧 —— 快速捏合时肉眼即为抖动。
3. 不要再尝试「运动中不重绘、只给画布套 CSS 变换让合成器搬运」。看似免费，
   任何一帧走了重绘分支而变换没同步就会先退后弹，用户实测为严重抖动。
4. 争议区标注锚点必须在 `fitExtent` **之后**算（`eaAnchors` 惰性 + 投影变更即失效）。
   `enterHist` 的顺序是 drawHist → fitExtent，早期版本在 drawHist 里算，锚点会飞到屏幕外。
5. 换档要分帧渐进烘焙（`eaBakeLeft`）、各图层按需解码。一次性做完实测卡 1.3 秒。
